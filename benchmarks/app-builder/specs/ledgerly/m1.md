Build **Ledgerly**, a double-entry bookkeeping app. Milestone 1: authentication, the chart of accounts, and manual journal entries.

**Auth.** Use the project's managed email/password authentication service; no hand-rolled auth, no social providers. Write your own sign-up and sign-in forms, not the prebuilt auth view. Sign-up takes name, email and password and signs the user in immediately; sign-in takes email and password. A failed submission shows its message in the error element, never throwing. Signed out, every route redirects to `/auth/sign-in`; `/` goes there signed out, to `/accounts` signed in. The header shows the signed-in email and a sign-out control.

**Money and dates.** Money is whole cents in integer columns, never floating point, at rest or in a sum. Every monetary JSON field is an integer of cents named `…Cents`; forms take and show dollars with two decimals and convert exactly: `1250.10` is `125010`, never `125009`. Entry dates are calendar dates in a `date` column, sent and returned as `YYYY-MM-DD`, never shifting by a day. Ids are UUIDs, not sequential integers — but not the session user id: it is an opaque 32-character string, so store every reference to it as `text`, never `uuid` or an integer.

**Chart of accounts.** A new user starts with an empty chart and journal — seed nothing. An account has a code unique per user, a name and a type of exactly `debit` or `credit`, its normal balance direction. `/accounts` sorts by code, and a code already in use is refused with nothing created.

**Journal entries.** An entry has a date, a memo and two or more lines; each line names one account and carries a debit and a credit, exactly one of which is above zero. It is valid only when total debits equal total credits and that total is above zero. Invalid entries are rejected and nothing written: 400 with `{ "error": "<message>" }` from the API, the message in `entry-error` from the form. The form shows three line rows and ignores a blank one; `entry-submit` is never disabled, so an unbalanced submit shows the reason in `entry-error`.

**Ownership.** Everything belongs to its creator: every query filters by the session user's id in server code, and no user reads or modifies another's records. Design the schema yourself and create it by executing SQL against the database.

**Routes** (exact paths). `/auth/sign-up`, `/auth/sign-in`; `/accounts`, `/accounts/new`; `/journal` (newest date first), `/journal/new`, `/journal/[id]`.

**JSON API.** `GET /api/me` returns the caller's own `{ id, email, name }`. Also `GET|POST /api/accounts`, `GET|POST /api/entries`, `GET /api/entries/[id]`. Lists return arrays of objects each with an `id`; create returns the created object with its `id`. Accounts carry `id`, `code`, `name`, `type`; entries carry `id`, `date`, `memo`, `totalDebitCents`, `totalCreditCents`, plus `lines` of `{ id, accountId, debitCents, creditCents }` on the detail endpoint. `POST /api/entries` takes `{ date, memo, lines: [{ accountId, debitCents, creditCents }] }`. Without a session every endpoint returns 401 and no data; authorize on the server.

**`data-testid` attributes (exact, on the described element).** Anything showing an entry date also carries `data-entry-date="YYYY-MM-DD"`.

- Sign-up `signup-name`, `signup-email`, `signup-password`, `signup-submit`, `signup-error`; sign-in `signin-email`, `signin-password`, `signin-submit`, `signin-error`.
- Header `user-menu` (contains the signed-in email), `sign-out-button`, `nav-accounts`, `nav-journal`.
- Accounts `accounts-list`, `accounts-empty`, `account-new-button`; per row `account-row` (also `data-account-id`) wrapping `account-row-code`, `account-row-name`, `account-row-type`. Form `account-form-code`, `account-form-name`, `account-form-type` (a `<select>` with values `debit` and `credit`), `account-form-submit`.
- Journal `journal-list`, `journal-empty`, `entry-new-button`; per row `entry-row` (also `data-entry-id`, `data-entry-date`) wrapping `entry-row-date`, `entry-row-memo`, `entry-row-total`, `entry-row-link`.
- Entry form `entry-form-date` (an `<input type="date">`), `entry-form-memo`; per line `entry-line-row` wrapping `line-account` (a `<select>` whose option value is the account id, labelled `<code> <name>`), `line-debit`, `line-credit`; then `entry-submit`, `entry-error`.
- Entry detail `entry-detail-date` (also `data-entry-date`), `entry-detail-memo`, `entry-detail-total-debit`, `entry-detail-total-credit`; per line `entry-line` wrapping `entry-line-account`, `entry-line-debit`, `entry-line-credit`.

Make it work end to end before you finish.
