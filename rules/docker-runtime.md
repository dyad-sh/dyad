# Docker runtime (isolated mode)

- In Docker mode (`runtimeMode2 === "docker"`) app-controlled code (package scripts, dependency install scripts, the app's own `typescript`/`@playwright/test`, configs, specs, git hooks) must never run on the host. Route it through `runGuestStreaming` / `runGuestBuffered` with `appGuestInput` / `snapshotGuestInput` from `src/ipc/services/docker_runtime/guest_command.ts`, or refuse with `assertSupportedOutsideDocker`. Any new file that starts a process must be classified in `host_process_inventory.test.ts`; that test fails until it is.
- Guest env is explicit: pass only the keys a command needs. `buildGuestInvocation` forwards them as `-e KEY` (the value comes from the Docker client's env) so secrets never appear in argv. Never pass `process.env` or `getPackageManagerCommandEnv()`.
- pnpm 11 reads only `pnpm_config_*` env vars for its own settings and silently ignores `npm_config_*` (verify with `pnpm config get <key>`). Symptoms: the store lands in the container's throwaway `/root/.local/share/pnpm/store`, or `npm_config_strict_dep_builds=false` still fails with `ERR_PNPM_IGNORED_BUILDS`. Set both spellings, or use `--config.*` flags. `pnpm exec` re-runs an install check first, so it hits the same error unless strict dep builds are disabled.
- Mounting the `dyad-nm-<appId>` volume under the bind-mounted app dir leaves an empty `node_modules` directory on the host. Host code must not treat its existence as "dependencies installed"; in Docker mode the host has no usable `node_modules`.
- Real-Docker tests: `DYAD_DOCKER_TESTS=1 npm test -- src/ipc/services/docker_runtime/docker_isolation.docker.test.ts`. With Colima, point `DOCKER_HOST` at the profile socket (`colima start` switches the global Docker context; restore it with `docker context use default`) and set `TMPDIR` to a directory Colima mounts, or bind mounts show up empty. Give each test case its own app ID: cases that share a `dyad-nm-<id>` volume see each other's `node_modules`.
