Build **Relay CRM**, a CRM web app. This first milestone covers authentication plus contacts and companies.

**Auth.** Use the project's managed email/password authentication service — do not hand-roll auth, and do not add social providers. Write your own sign-up and sign-in forms (not the prebuilt auth view component) so the inputs carry the exact test ids listed below. Sign-up collects name, email and password and signs the user in immediately; sign-in takes email and password. Failed submissions show the error message in the error element instead of throwing. Visiting any app route while signed out redirects to `/auth/sign-in`. `/` redirects to `/auth/sign-in` when signed out and to `/contacts` when signed in. A header shows the signed-in user's email and a sign-out control.

**Features.** Contacts have name, email, phone, title and an optional company. Companies have name and domain. Both support create, read, update and delete from list and detail pages. The contacts list has a search box that filters the visible rows by name or email. A company detail page lists the contacts linked to that company. Every record belongs to the user who created it: all database queries must filter by the session user's id in server code, and one user must never be able to see or modify another user's records. Design the schema yourself and create it by executing SQL against the database.

**Routes (use exactly these paths).**

| Route                                                    | Purpose                |
| -------------------------------------------------------- | ---------------------- |
| `/auth/sign-up`, `/auth/sign-in`                         | auth forms             |
| `/contacts`                                              | contacts list + search |
| `/contacts/new`, `/contacts/[id]`, `/contacts/[id]/edit` | create, detail, edit   |
| `/companies`, `/companies/new`, `/companies/[id]`        | list, create, detail   |

**JSON API (also required).** `GET /api/me`, `GET|POST /api/contacts`, `GET|PATCH|DELETE /api/contacts/[id]`, and the same four for `/api/companies`. `GET /api/me` returns the calling user's own `{ id, email, name }` as JSON and HTTP 401 when there is no valid session. List endpoints return a JSON array of objects each with an `id`; create returns the created object including its `id`. Requests without a valid session return HTTP 401 and no data. All authorization happens on the server.
