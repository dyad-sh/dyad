Milestone 3: workspace roles, an activity timeline, CSV export, and security hardening. Everything from milestones 1 and 2 must keep working.

**Roles.** Each membership has exactly one role: `owner`, `member`, or `viewer`. Owners can do everything, including inviting people, changing a member's role, and removing members. Members can create, edit and delete contacts, companies and deals, but cannot manage members or invites. Viewers have read-only access: no creating, editing or deleting anything. Enforce this **on the server in every route handler** — hiding buttons is not enough, and a request from a viewer or member that exceeds their role must return HTTP 403 and change nothing. Nobody may change their own role, and a workspace must always keep at least one owner. Also reflect roles in the UI: hide create/edit/delete controls from viewers, and hide the members navigation from non-owners. The invite form gains a role selector so people can be invited as member or viewer. `GET /api/me` continues to report the caller's own membership id and role per workspace, and `GET /api/workspaces/[id]/members` (owners only) continues to return each member's membership `id`, `userId`, `email` and `role`.

**Activity timeline.** Each contact's detail page shows a reverse-chronological timeline of activity for that contact: automatically recorded system entries when the contact is created or updated and when a linked deal changes stage, plus notes any member can add from a note box (viewers can read the timeline but not add notes). Each entry shows its type, its text, who did it, and when.

**CSV export.** A button on the contacts list downloads the active workspace's contacts as CSV. It is a link or handler that issues an authenticated `GET /api/export/contacts.csv` at exactly that path; that route responds with `Content-Type: text/csv`, a `Content-Disposition: attachment` filename, a header row exactly `name,email,phone,title,company`, and one row per contact. The same route must return the identical CSV body to a plain authenticated GET (no browser-only behaviour). The export contains only the active workspace's contacts and requires an authenticated member of that workspace; unauthenticated requests return 401.

**Validation and hardening.** Validate every write endpoint's body server-side: reject a missing/blank contact name, a malformed email, a non-numeric or negative deal amount, a stage outside the five allowed values, and any string longer than 500 characters, with HTTP 400 and a JSON body `{ "error": "<message>" }`; the form shows the message in its existing error element. Ignore client-supplied fields that must not be settable — `id`, workspace id, membership id, role, owner/creator id — on create and update; a record must never move between workspaces because of a request body. Keep all database access and authorization server-side.

**Routes.** New: `POST /api/contacts/[id]/activities`, `GET /api/contacts/[id]/activities`, `GET /api/export/contacts.csv`, `PATCH /api/workspaces/[id]/members/[memberId]` (role change), `DELETE /api/workspaces/[id]/members/[memberId]`.
