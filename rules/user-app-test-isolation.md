# User-app test isolation (Tests panel)

Applies to `src/ipc/services/isolated_test_db.ts`, `test_case_lifecycle_server.ts`, `src/ipc/utils/supabase_test_user.ts`, `neon_test_data.ts`, and the generated Playwright fixture shim in `playwright_bootstrap.ts`.

- **Discover cleanup targets from `pg_class`, not `information_schema.columns`.** The latter also lists views, and `DELETE` on a non-updatable view fails with `55000 cannot delete from view` (seen in user logs as `Best-effort cleanup of public.<view>... failed`). Filter `c.relkind IN ('r', 'p') AND NOT c.relispartition`, as `neon_test_data.ts` and `supabase_test_user.ts` do.
- **Per-test lifecycle work runs before every test case, so each Management API round trip multiplies.** Batch per-table SQL into one request, giving each statement its own `BEGIN … EXCEPTION WHEN others … END` so one failing table does not roll back the others. A `DO` block cannot return rows, so to report per-table errors use a `CREATE OR REPLACE FUNCTION pg_temp.…` that returns them, followed by `SELECT` (this assumes the Management API returns the last statement's rows, which unit tests cannot confirm — parse the result defensively). `WHEN others` does **not** catch `QUERY_CANCELED`, so a statement timeout still rolls back the whole block; keep a per-statement fallback, since separate requests commit independently. SQL is mocked in the unit tests, so they cannot catch transaction semantics like this.
- **The per-test timeouts are nested and must move together:** server hook (`TEST_CASE_HOOK_TIMEOUT_MS`) < fixture `fetch` (`TEST_CASE_REQUEST_TIMEOUT_MS`) < Playwright fixture timeout (`TEST_CASE_FIXTURE_TIMEOUT_MS`), all derived in `test_case_lifecycle_server.ts`. Raising only the server value just turns a clear timeout error into a bare client abort. The fixture shim is regenerated on every run (while it carries the Dyad sentinel), so shim-side changes need no config migration.
- **Supabase fixture admin credentials belong only in `PreparedIsolation.testRunnerEnv`.** Inject `SUPABASE_SECRET_KEY` and the matching `SUPABASE_URL` into the Node Playwright runner in both sandbox and normal-preview paths; keep them out of dotenv files, install/dev-server environments, recorder auth, IPC results, and telemetry.
- Redact runner-only environment values before streaming output or returning results. Buffer partial credentials across pipe chunks and strip ANSI highlighting before matching; Playwright assertion diffs can insert escape codes inside a secret. Verify with a real spec that prints the key and fails an assertion on it.
- **Dyad's automatic user provisioning precedes spec `beforeEach` hooks.** Per-case Supabase tests may continue without default credentials only after a recognized HTTP 500 database-create rejection and a read-only check that no auth user exists for the attempted email. Recognize both Auth's generic error and structured PostgreSQL constraint (SQLSTATE class 23) or raised-exception (`P0001`) errors, never arbitrary message text. Other errors, cancellation, and cleanup failures remain fatal; recordings still require successful provisioning. Custom fixtures own cleanup of their users and prerequisite rows.

- Tests that mock or skip Playwright bootstrap but launch a real runner must generate its DNS preload with `ensurePreviewDnsPreload`; otherwise Node fails before the spec loads. Assert preload paths against `await fs.promises.realpath(appPath)`, matching the runner's native path resolution; `fs.realpathSync` can retain Windows 8.3 aliases such as `RUNNER~1` while the runner expands them to `runneradmin`.
