We are building "Portalis", a B2B SaaS admin portal, in this Next.js app. Postgres and the managed auth service are already connected and their environment variables are already injected — do not create or provision any new database or auth project. Email verification is disabled: a successful sign-up must leave the user signed in immediately.

Milestone 1 scope:

1. Email/password sign-up and sign-in (no social providers). Build your own sign-in and sign-up forms rather than a prebuilt drop-in auth widget, but use the managed auth service for the actual account/session handling — never hand-roll password hashing or session tokens.
2. Signed-in users land on `/orgs`. With no organizations, show an empty state plus a link to create one.
3. `/` is not a landing page: signed-out visitors are redirected to `/auth/sign-in`, signed-in visitors to `/orgs`.
4. `GET /api/me` returns JSON `{ id, email, name }` for the signed-in caller and `401` when there is no session. `id` MUST be the same user id your app stores on membership rows.
5. Organization creation: `name` and a unique lowercase `slug`. The creator becomes the org's first member with role `org_admin`.
6. Org overview page with the org name and links to Settings and Members.
7. Org settings: edit name and description; changes persist and are reflected on `/orgs`.
8. Members page: table of members with email and role, plus a member count.

Hard requirements:

- Every id exposed in a URL or API response (orgs first of all) MUST be a UUID, never a sequential integer.
- Every member row in a member list MUST carry `data-user-id` equal to that member's user id — the same value `GET /api/me` returns as `id` for that user.
- Every page and request under `/orgs/{orgId}` MUST verify server-side that the signed-in user is a member of that org. Signed-out visitors are redirected to `/auth/sign-in`; signed-in non-members must not see any org data.
- Authenticated pages must reflect writes immediately — do not cache authenticated data across requests.
- Design the schema yourself and create it with the database tooling available in this environment.

Routes (exact):

| Route                    | Purpose                                                            |
| ------------------------ | ------------------------------------------------------------------ |
| `/`                      | redirect only: to `/auth/sign-in` signed out, to `/orgs` signed in |
| `/auth/sign-up`          | sign-up form                                                       |
| `/auth/sign-in`          | sign-in form                                                       |
| `/orgs`                  | orgs the user belongs to; empty state                              |
| `/orgs/new`              | create-org form                                                    |
| `/orgs/{orgId}`          | org overview                                                       |
| `/orgs/{orgId}/settings` | org profile settings                                               |
| `/orgs/{orgId}/members`  | member list                                                        |
| `/api/me`                | caller's own `{ id, email, name }`; `401` signed out               |
