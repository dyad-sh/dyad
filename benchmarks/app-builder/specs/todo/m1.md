Build **Tasklet**, a personal task tracker. This is the whole app in one milestone.

**Auth.** Use the project's managed email/password authentication service — no hand-rolled auth, no social providers. Write your own sign-up and sign-in forms, not the prebuilt auth view. Sign-up takes name, email and password and signs the user in immediately; sign-in takes email and password. A failed submission shows its message in the error element instead of throwing. Signed out, every app route redirects to `/auth/sign-in`; `/` goes to `/tasks` when signed in. A header shows the signed-in email and a sign-out control. **The session user id is an opaque 32-character string: store it as `text`, never a uuid or an integer.**

**Tasks.** A task has a title, an optional note, a priority (`low`, `medium`, `high`), a due date, and a done flag. A signed-in user creates, edits, completes, reopens and deletes their own tasks, and sees only their own — enforce this in server code, not by hiding controls. Creating a task with a blank title fails with a message in the form's error element and writes nothing.

**Lists and filtering.** `/tasks` lists the user's tasks newest first, with a filter for `all`, `open` and `done`, and a separate filter by priority. An empty list shows an empty-state element. Each row shows the title, priority and due date, and links to the task's detail page.

**Routes** (exact paths): `/auth/sign-up`, `/auth/sign-in`, `/tasks`, `/tasks/new`, `/tasks/[id]`, `/tasks/[id]/edit`.

**JSON API.** `GET /api/me` returns the caller's own `{ id, email, name }`, 401 with no session. `GET|POST /api/tasks`; `GET|PATCH|DELETE /api/tasks/[id]`. Lists return arrays of objects each carrying `id`; creates return the created object with its `id`. Task objects carry `id`, `title`, `note`, `priority`, `dueDate`, `done`. Requests without a session return 401 and no data; authorize on the server.
