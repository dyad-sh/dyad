Milestone 3: accounting periods, an audit trail, and hardening. Everything from milestones 1 and 2 keeps working.

**Periods.** A period has a name and an inclusive start and end date, belongs to the active book, and is `open` or `closed`; two periods in one book may not overlap, and an overlapping create is a 400 shown in `period-form-error`. Its `totalDebitCents` and `totalCreditCents` are the debits and the credits of posted entries dated inside it, both boundary dates included, and they are equal. Only an `owner` may close or reopen one; a `bookkeeper` sees the list read-only, gets no close or reopen control, and gets 403 from those endpoints. **While a period is closed nothing may change the posted ledger inside it.** Posting an entry dated inside it, creating one with `status: "posted"` dated inside it, reversing one dated inside it, and editing or deleting a draft dated inside it all fail with 409 and `{ "error": "<message>" }` — from the API and from the UI, where the message goes in the page's error element — and nothing is written. Reopening restores all of it. A draft dated inside a closed period stays a draft and shows `period-locked-badge`.

**Audit trail.** Every posting, reversal, close and reopen appends exactly one row to an append-only trail, in the same transaction as the change it describes, with exactly the actions `entry.posted`, `entry.reversed`, `period.closed`, `period.reopened`. Each row records the acting user's id and email, the target id and a timestamp. The actor is always the session user, never a value read from a request body. `/audit` shows the active book's trail newest first, filterable by action. No code path updates or deletes an audit row.

**Hardening.** Money stays exact: every amount is an integer number of cents at rest, in every sum and in every JSON field, so no volume of entries makes an account balance or a period total drift from an exact integer. Posted entries stay immutable, and a reversal is always an exact mirror of its original: ignore any `lines`, amount, `bookId`, `date`, `status`, `entryNumber`, `id`, actor or role field in a post or reverse request body. Resolve the book and the caller's membership and role from the database on every request, never from a cookie, header or body; a non-member gets no data from any route, including periods and audit. Validate every write server-side with 400 and `{ "error": "<message>" }` for a blank account code or name, an unknown account type, an amount that is negative or not a whole number, a date that is not `YYYY-MM-DD`, a period whose end precedes its start, and any string over 500 characters.

**Routes.** `/periods`, `/periods/[id]`, `/audit`. New API: `GET|POST /api/periods`, `GET /api/periods/[id]`, `POST /api/periods/[id]/close`, `POST /api/periods/[id]/reopen`, `GET /api/audit?action=`. Periods carry `id`, `name`, `startDate`, `endDate`, `status`, `totalDebitCents`, `totalCreditCents`; audit rows carry `id`, `action`, `actorUserId`, `actorEmail`, `targetId`, `createdAt`.

**`data-testid` attributes (exact).** `data-period-start` and `data-period-end` are `YYYY-MM-DD`; `data-audit-time` is an ISO-8601 timestamp.

- Periods list `nav-periods`, `periods-list`, `periods-empty`; per row `period-row` (also `data-period-id`, `data-period-start`, `data-period-end`) wrapping `period-row-name`, `period-row-range`, `period-row-status`, `period-row-link`; then `period-new-name`, `period-new-start`, `period-new-end`, `period-new-submit`, `period-form-error`.
- Period detail `period-detail-name`, `period-status` (text exactly `open` or `closed`), `period-close-button`, `period-reopen-button`, `period-total-debit`, `period-total-credit`, `period-error`.
- Audit `nav-audit`, `audit-list`, `audit-empty`; per row `audit-row` (also `data-audit-id`, `data-audit-action`, `data-audit-time`) wrapping `audit-row-action`, `audit-row-actor` (the actor's email), `audit-row-target`, `audit-row-time`; then `audit-filter-action` (a `<select>` with option values `all`, `entry.posted`, `entry.reversed`, `period.closed`, `period.reopened`) and `audit-filter-apply`.
- Entry detail `period-locked-badge` on an entry dated inside a closed period, and `entry-error` for the message when a post, reversal, edit or delete is refused.
